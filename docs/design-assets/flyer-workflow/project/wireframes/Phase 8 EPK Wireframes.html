Purpose

First screen of every new project. Branches Music Promo (existing) from EPK Carousel (new). Reached either by tapping the Create tab or the + FAB on Home.

Anatomy

  • 1Dismiss. Only renders when presented as a stack push (e.g. from the FAB). When the screen is tab-embedded (via (tabs)/create.tsx) the close button is hidden — switching tabs is the dismiss.
  • 2Music Promo card. Tap → /create/picker. Identical to today's entry; no visual change.
  • 3EPK Carousel card. Tap → /create/epk/details. NEW badge for v1; remove after 2 weeks of release. Description copy is fixed: it must mention "4-slide" and "Instagram" so users self-select correctly.

States

  • Default. Both cards equal weight. No selection state — tap navigates immediately.
  • Pressed. Card opacity 0.8 + scale 0.985 (system press style).
  • Tab-embedded. Close button suppressed; tabEmbedded prop true.

Edge cases a designer would catch

  • If user reaches this screen and the type-picker analytics fires twice (once on tab press, once on mount), the first event should win. Code already debounces via previousPathnameRef — keep this.
  • After EPK launch hits 2 weeks, drop the "New" badge. Do not leave it indefinitely.
  • Card order matters: Music Promo first (familiar), EPK second (new). Do not A/B-test order — alphabetical reads as demoting EPK.
  • If a third project type is ever added, this becomes a list rather than two large cards. Plan for that — keep the card markup repeatable, not absolutely positioned.

Purpose

Collect the two minimum facts about the track: artwork and title. Offers a power-user shortcut: pre-fill both from an existing Music Promo project.

Anatomy

  • 1Header. Back chevron + screen name + 1 of 3 step counter. Step counter is right-aligned, secondary color — never bold.
  • 2Artwork well. 1:1 aspect, dashed border when empty, solid when filled. Filled state shows a [Change] chip overlay on tap-and-hold; this is the only entry to re-pick.
  • 3Link affordance. Tapping opens a page-sheet modal listing prior Music Promo projects (thumbnail + title + date). Selecting one fills artwork + title and shows a "Linked" badge in place of this row. The × on the badge unlinks but does not clear the filled fields — by design.
  • 4Title input. Single line, 80-char cap (no counter). Placeholder example is concrete, not abstract.
  • 5Next. Disabled at 0.3 opacity until both artwork and trimmed title are present. Validates on press, not on blur.

State variants

  • Empty (shown). Both fields blank, Next disabled.
  • Linked. Artwork filled from existing project. Link row replaced by a chip: ✓ Linked [×]. Title pre-filled, editable. Template + clip length captured silently and forwarded to the Track Details slide.
  • Photo loading. Artwork well shows a centered spinner; tap ignored.
  • Permission denied. Native alert from ImagePicker; well stays empty.
  • No prior projects (guest). Modal empty state: "Sign in to link an existing Music Promo."

Edge cases

  • User picks a HEIC photo. Force preferredAssetRepresentationMode = Compatible so downstream FFmpeg/slide capture doesn't choke (mirrors picker.tsx).
  • User links a project whose photo file no longer exists locally (cleared cache). The link-picker list itself should hide those projects rather than 404 the EPK flow.
  • Title with only whitespace must not advance — currently guarded by title.trim(). Keep.
  • Linking pre-fills title — but what if the linked project's title is empty? Today it pre-fills with ""; design intent is: leave the title field focused and empty so the user types one. Worth a test.
  • Modal sheet uses native iOS pageSheet — back-swipe-to-dismiss is expected. Don't add a redundant Cancel chevron.

Purpose

Capture the artist's voice in one paragraph. This text becomes the Slide 3 block-quote — the centerpiece of the carousel.

Anatomy

  • 1Track strip. Thumbnail + title from Step 1, read-only. Anchors the user — they're writing about this track, not in the abstract.
  • 2Vision input. Multiline, autofocus on mount, soft keyboard-aware. Min height ~180px so the field looks invitingly large. Placeholder is the literal product question, not "Enter description".
  • 3Live counter. Counts remaining (not used). Turns warning-red (#FF6B6B) at remaining ≤ 30. Bottom-right of card, not floating.

State variants

  • Empty. Placeholder visible, counter 280, Next disabled.
  • Filling. Counter ticks down. Field grows? No — fixed min-height, internal scroll if user pastes a wall of text.
  • Approaching limit (≤ 30 chars). Counter turns red. Input continues to accept up to 280, then hard-stops (no truncation alert).
  • At cap. Counter shows 0 in red. Next is enabled. Further keystrokes are silently dropped.

Edge cases

  • Whitespace-only string must not enable Next. Already guarded by vision.trim().length > 0.
  • Paste > 280 chars. We truncate silently rather than rejecting — friendlier than the iOS native ding. (Spec is silent; mirror SMS-style truncation.)
  • Hardware keyboard / iPad split keyboard: avoid covering the Next button. KeyboardAvoidingView with behavior="padding" already handles this.
  • The vision is forwarded as a URL param. 280 chars is well within param limits — no need for AsyncStorage handoff.
  • Back navigation does not warn about unsaved text. v1 acceptable; if drop-off is high, add a haptic confirm.

Purpose

Final review + export. Full-screen swiper through all 4 slides; one button to save them all to the Camera Roll.

Anatomy

  • 1Slide canvas. One slide fills the available width. Aspect is 1:1 visually but the capture surface is rendered at SLIDE_WIDTH × 5/4 for IG safe area (matches current preview code). Horizontal pageable swiper. The right-column "step" indicator switches from 1 of 3 to the slide name (Cover / Track Details / Vision / Bio).
  • 2Slide counter. Tiny n/4 overlay top-right of the slide itself. Decorative, not the source of truth (the dots are).
  • 3Dot pagination. Active dot is a pill (18×5), inactive dots are 5×5 circles at 30% opacity. Tap-on-dot is not a navigation affordance — swipe only. (Open question: do we want tap-to-jump? Not in the spec.)
  • 4Profile nudge. Rendered only when !bio && links.length === 0. Tap → /profile. Persists across all 4 slides — does not animate per-slide.
  • 5Export. Single primary CTA, fixed bottom. Captures each slide via captureRef, saves 4 JPGs to MediaLibrary, then alerts "4 slides saved to your Camera Roll. Open Instagram and create a carousel post." Replaces back-stack with Home.

State variants

  • Default. All four slides render; nudge hidden if profile is complete.
  • Nudge visible. Profile incomplete; banner sits above the export CTA. Banner is dismissible only by completing the profile (no ×).
  • Exporting. Export button shows spinner + "Exporting…". Button disabled. Swipe still enabled.
  • Permission denied. Native alert: "Allow access to your photo library to save the slides." Button returns to idle on dismiss.
  • Re-open from Home. If user taps an existing EPK project, lands here with all data pre-filled. Export updates the existing project (status: "exported") rather than creating a new one. Header back chevron returns to Home, not Vision.

Edge cases

  • Capture timing. Slide 4 has a remote avatar — captureRef can fire before the image decodes. Add an onLoad race plus a 500ms floor (mirror the profile share card pattern).
  • Slide order in Camera Roll. iOS Photos sorts by capture timestamp. Save sequentially with a tiny await between, so order is preserved (1 → 4) when the user multi-selects in Instagram.
  • Vision text overflow. 280 chars + curly quotes can run off slide 3 at certain dynamic-type sizes. The slide should auto-scale font from 28→22pt; do not truncate.
  • Missing avatar on slide 4. Render the default avatar JPG, never an empty circle.
  • No social links. Slide 1 social-icons row collapses — don't render empty dots. Slide 4 row hides entirely.
  • Pull-to-back gesture. Disabled on this screen (gestureEnabled: false) so a horizontal swipe doesn't accidentally pop back. Keep.
  • Memory. Four full-bleed View captures + 4 JPGs can spike on older iPhones. Use quality: 0.93 JPG (current) and capture sequentially, not in parallel.

Slide-level edge cases

  • Long artist names. Slide 1 small-caps name should wrap rather than truncate; max 2 lines. Display title on Slide 2 has higher priority — it can shrink to keep the artist name intact.
  • Single-word track title. Slides 1 + 2 should not force a line break — let the type rag naturally.
  • No social links. Slide 1 icon row hides; slide 4 icon row hides. Don't render empty placeholders on export.
  • Bio > ~140 chars. Slide 4 should clip at 140 with an ellipsis rather than overflow the avatar/name area.
  • Vision quote escape. User types a literal " in their vision — render as curly per surrounding punctuation rules. Don't double-encode.
  • Slide 2 secondary meta. If clip length is missing (fresh-start path, no linked project), the line collapses to just the template name. If template name is also missing, hide the line entirely — don't render · with nothing on either side.

Purpose

Differentiate EPK projects from Music Promo projects at a glance, in the existing 2-column grid. No layout change — only a badge overlay + a swapped date subtitle.

Anatomy

  • 1EPK badge. Pill, 8pt all-caps, 0.18em tracked, on solid --ink background. Anchored top-left inside the thumbnail with 8px inset. Always above any thumbnail image. Aspect of the thumbnail itself does not change — keep 9:16 even for EPK projects, using the cover artwork; the slides themselves are 1:1 but the project thumbnail is the artwork.
  • Subtitle swap. Music Promo cards show formatDate(createdAt). EPK cards show the string "EPK Carousel" (mirrors the existing renderProjectCard branch in (tabs)/index.tsx).

Edge cases

  • Multi-select. Selection checkmark badge sits top-right (existing behavior). Badge stays top-left — they don't conflict.
  • Long titles. Both card types truncate to 1 line. No special treatment for EPK.
  • Tap target. Tapping an EPK card opens directly to the Preview screen with all fields rehydrated (existing route handles this). Long-press still opens multi-select.
  • Sort. Mix EPK and Music Promo chronologically by createdAt — do not group by type. Differentiation is the badge, not the layout.
  • Future: filter chip ("All / Music Promo / EPK") at top of grid. Not v1, but reserve space mentally — header right-actions are already tight.

Notes on routing. The Type Picker is also embedded directly into the (tabs)/create.tsx tab via a tabEmbedded prop, so tapping the Create tab lands on the same UI without a stack push or close button. Both entry paths reach the same flow.
