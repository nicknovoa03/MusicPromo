Flyer Design System

A reference for the Show Flyer workflow inside MusicPromo — the third creation flow, slotted next to Music Promo (video) and Song Press Kit (carousel).

This document layers on top of the main MusicPromo system (README.md + colors_and_type.css). Chrome, voice, iconography, spacing, and motion are inherited unchanged. What's new is the flyer artifact itself and the small set of editor surfaces that produce it.

What a flyer is

A flyer is a single, square-ish artwork announcing a live show. It exports two ways:

OutputAspectUse
Video (MP4)9:16 / 4:5Story or Reel with a short audio bed and subtle motion (grain shimmer, ticker)
Image (PNG)9:16 / 4:5Static feed post, screenshot for DMs, print poster source

The flyer carries the show's identity, not the app's. It's a designed poster — bold typography, textured surfaces, a single decisive accent. The MusicPromo wordmark appears once, small, in a corner. Everything else is the artist's.

Required fields

A flyer is generated from a fixed schema. Every template renders the same fields — visual treatment changes, data doesn't.

FieldRequiredNotes
eventName✓1–3 words is the sweet spot. Long names auto-scale.
date✓Always uppercase, weekday + month abbrev (SAT APR 25).
time✓4PM – 8PM style. Em dash between, no leading zeros.
venue✓Free-form, single line.
city–City, ST — appended after venue if present.
lineup–Object containing up to 10 performers plus layout controls. See Lineup system section. Drops off the layout entirely if items is empty.
eyebrow–Category tag (ROOFTOP DAY PARTY). All caps, letter-spaced.
tagline–Genre line (house / disco / grooves). Lowercase, slash-separated.
age–18+, 21+. Renders as a stamp, never inline.
photo–User-supplied artwork. Replaces the textured background.
audio–10–30s clip for video export. No effect on the image export.
Defaults > placeholders. Every field has a sensible default render when empty. The flyer should always look complete, even partially filled.

Lineup system

The lineup is the most dynamic part of the flyer. It is a self-contained visual block — LineupBlock — that every template declares a zone for. Templates position and size the zone; the block fills it. This keeps lineup logic in one place and makes new templates trivial to add.

Schema

PropertyTypeNotes
itemsLineupItem[]0–10 performers, in display order.
showSetTimesbooleanControlled by a toggle in the Text tab. When off, times are stored but invisible.
layoutLineupLayoutOne of four variants (see below). Auto-suggested from count; user can override.
introLabelstring | nullLabel rendered above the block: SOUNDS BY, MUSIC BY, DJ SET BY, FEATURING, WITH, or a custom value. Null hides the label.

Each LineupItem:

PropertyTypeNotes
namestringPerformer name. Always uppercase on the flyer.
headlinerbooleanAt most one per flyer. Name renders in the template's display font, scaled to fill its slot. All others use the standard lineup face.
setTimestring | nullStart-only, no leading zero, uppercase single-letter suffix — 9PM, 11PM, 2AM. Only visible when showSetTimes is true.

Intro label

The intro label sits above the lineup block in the LABEL style (all caps, letter-spaced, muted). It contextualises the list without adding a heading. For single-performer flyers, this is the primary framing device — the performer name becomes display-size and the label does the explaining.

The field is fully free-text — the user types whatever they want. Five presets are offered as a starting point, but the custom input is always first-class, not a fallback:

  • SOUNDS BY
  • MUSIC BY
  • DJ SET BY
  • FEATURING
  • WITH

The picker UI shows these as tappable pills. Tapping a pill fills the text field; the user can then edit it freely. There is no restriction on what this label says.

Single-performer rule. When items.length === 1, the layout prop is ignored. The name renders at display scale in the template's headline font, with introLabel above it. The flyer reads like a headliner announcement — not a list of one.

Headliner treatment

Equal billing is the default. When no headliner is set, all names render at the same weight and scale — position in the list and set times are the only hierarchy signals. This is intentional: not every show has a headliner, and the system should never pressure a user to designate one.

Set times naturally do this work when equal billing is preferred. A closer at 11PM reads differently from an opener at 7PM without any name needing to be called out. This is the preferred pattern for multi-act lineups where all acts are peers.

If the user does want to call out a headliner, they opt in via ⋯ → Set as headliner on any row. Rules:

  • At most one headliner per flyer — setting a new one clears the previous.
  • Name renders in the template's display font (Anton / Bebas Neue / Pinyon Script) at a larger scale than the supporting acts.
  • In Grid and Column layouts, the headliner row is visually separated — full width, display type — with supporting acts in the standard lineup face below.
  • Headliner can be cleared at any time (⋯ → Remove headliner) — the flyer reverts to equal billing instantly.

Set times toggle

A binary toggle in the Text tab, below the lineup list. When toggled off, the setTime values are preserved in the data — they just don't render. This lets a user build the schedule privately, then reveal it by toggling on. When on, times appear in the template's accent color above (Grid) or right-aligned beside (Column / Festival) each name.

Editor UX for the lineup

  • Add — "Add performer" row at the bottom of the list; dashed border, + icon, same height as a real row.
  • Reorder — drag handle (⠿) on the left of each row. Long-press to activate drag. Reorder is position-in-list order, not time order — the user controls it.
  • Delete — swipe-left reveals a red trash pill; or tap ⋯ → Remove.
  • Set headliner — tap ⋯ → Set as headliner. Row gains a star badge on the right.
  • Set time input — inline text input on each row, visible only when the set-times toggle is on. Placeholder: 9PM.
  • Intro label — tapping the label above the list opens a sheet: five preset pills + a custom text field.

What modular means in practice

A template declares a lineup zone as a rectangular area with a max width and a vertical position. The LineupBlock component receives the lineup object and fills that zone — it never bleeds outside it. When space is tight (small poster preview, 10-act festival layout), the block scales its internal type sizes uniformly so it always fits without truncating names.

This means: adding a new template requires no lineup code. Changing the layout variant in the editor hot-swaps the block in the live preview instantly. Exporting always uses the same block — no separate render path.

Voice for flyer copy

Inherits the MusicPromo voice (operational, no fluff, no emoji), with two flyer-specific rules:

  • Type does the shouting, not punctuation. Never an exclamation point on a flyer.
  • Abbreviate dates and times. THURS MAY 14, 8PM – 12AM — never Thursday, May 14th 2026.

Templates

Three templates ship with the feature. They are deliberately different visual grammars — picking one is a stylistic commitment, not a color choice. Users retune inside a template; they don't morph between them.

TemplateMoodTypeColor
HeatTextured, late-night, halftoneAnton + Caveat + InterDark radial + one warm accent
IridescentBright, holographic, sticker-packBebas Neue + Anton + InterPastel gradient + pure black ink
VintageWarm grain, '70s-era, softPinyon Script + Anton + InterEarthy radial + dark brown ink

Heuristic — which template

  • Late-night DJ set, club, party → Heat
  • Bright daytime event, pool, festival → Iridescent
  • Acoustic, lounge, listening room → Vintage

Every template guarantees

  • Renders the same field schema
  • Watermark in the bottom-right, small, low-contrast
  • Works at 9:16 and 4:5 without re-layout (linear scale)
  • Safe area of 5% on every edge for Story chrome

Editor anatomy

The editor is always dark, regardless of system theme. It's where the artifact is born — the editorial theme is part of the artifact's voice.

  1. Nav (44pt) — Close (×) · project name (centered, muted) · Export pill. No back chevron.
  2. Preview area — Centered live render. Aspect badge top-right. The one place in the app where drop shadow is allowed (it's a screen-within-a-screen).
  3. Template rail — Horizontal scroll · Heat / Iridescent / Vintage. Active pill is white-on-black.
  4. Tabs (5) — Text · Colors · Fonts · Photo · Audio. 2px white underline marks active.
  5. Tab content — Scrolls inside the sheet, never the preview.

Tab contracts

TabWhat's inside
TextPer-slot inputs: eyebrow, title, subtitle, lineup, footer. Selected slot mirrored in preview with a yellow ring.
ColorsTwo palettes side-by-side: BACKGROUND (6 swatches) + ACCENT (6 swatches). Active wears a white ring.
FontsDisplay pair + Script pair, rendering "DISCO" or "at dusk" in each candidate.
PhotoDrop zone. Replaces the textured background. Includes opacity slider (0–60%) and "Remove photo".
AudioWaveform with two yellow trim handles. Selection caps at 30s.
Preview ⇄ Edit linkage. Tapping any text in the preview jumps to Text tab with that slot focused. Long-press a colored region → Colors tab. The preview is interactive — not just a render.

Export sheet

A separate full-screen dark sheet reached via the Export pill.

  1. Centered re-render of the flyer (~180×320)
  2. Format — Video MP4 (default) · Image PNG. Radio-style cards.
  3. Aspect — 9:16 Story · 4:5 Post. Segmented toggle.
  4. Share to Instagram — gradient pill #F58529 → #DD2A7B → #8134AF. The only branded gradient in the app, justified because it's IG's identity, not ours.
  5. Save to Camera Roll — outline pill.

What this system is not

✗Not a free editor (v1). No drag-handles, no z-index, no "add layer." Templates are the layout — users edit content within slots, not the slots themselves. A zone-based editor is a later-phase consideration.
✗Not a color picker. Curated swatches only. Six per palette. No hex input, no eyedropper.
✗Not a font store. Three display faces, three script faces. Body is always Inter.
✗Not infinite. Ten performers max, four layout variants, one intro label, one headliner. One photo slot, one audio slot. Anything else is out of scope.

Open questions

  • Auto-generate from track data? If a user has a Music Promo for the same show, the flyer should pull artist / artwork / date metadata. Today they retype.
  • Multi-date / tour mode? Currently single-event. A 4-stop tour would need a new template.
  • QR ticketing. A separate slot, or part of the photo? TBD.
  • Story stickers (location, music link). Out of scope for v1 — IG/TikTok add these post-export.
  • Zone-based layout editor. A structured middle ground between template-locked and fully free — predefined snap zones, field-to-slot swapping. Deferred; revisit after v1 ships and user feedback clarifies what constraints feel limiting.
